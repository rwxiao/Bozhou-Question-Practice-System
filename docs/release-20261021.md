## 部署包范围

包中包含 app.py、requirements.txt、Dockerfile、两种 Compose 配置、Caddyfile、.dockerignore、.env.example、frontend 源码和锁文件、web/build 最新静态资源、ops 备份工具及部署文档。排除 Git、真实 .env、数据库、账号凭据、缓存、node_modules、虚拟环境、历史包和验收截图。

这是应用部署包，不是数据库迁移包。已有服务器升级时继续使用服务器原有 .env 和数据库卷。全新服务器启动会创建空数据库与配置的初始管理员；本地题库和学习记录不会随本包迁移。

## 已有腾讯服务器升级

先按服务器实际情况备份现有程序和数据库。上传压缩包后，在现有 `/opt/bozhou-practice` 目录解压，保留原 `.env`。执行：

```bash
docker compose -f compose.server.yaml run --rm --no-deps backup python ops/backup.py once
docker compose -f compose.server.yaml up -d --build practice backup
docker compose -f compose.server.yaml ps
docker compose -f compose.server.yaml logs --tail=100 practice backup
```

此模式复用现有 Caddy 网关，要求 `.env` 中 DOMAIN 正确，GATEWAY_NETWORK 指向实际网关网络；网关将该域名转发到 `bozhou-practice:8000`。不要执行 `down -v`，不要用本机数据库覆盖线上数据库。历史部署详情见 `docs/tencent-deployment.md`，其中旧版本信息仅作记录，以服务器现状为准。

## 全新独立服务器

安装 Docker 与 Compose，解压后复制 `.env.example` 为 `.env`，填写实际 DOMAIN、ADMIN_USERNAME 和至少 10 字符的随机管理员密码，限制 `.env` 权限。域名解析到服务器并开放 80/443，运行：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app proxy backup
```

此模式由自带 Caddy 占用 80/443；已有网关的服务器使用上一种模式。Docker 构建需要联网下载基础镜像、npm 和 Python 依赖。上线后检查 HTTPS、登录、题库、历史记录和备份日志。包内前端产物也支持按 README 在 Python 环境中运行。

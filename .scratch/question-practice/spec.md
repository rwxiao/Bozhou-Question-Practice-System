# 通用在线刷题网站：首版规格

Status: resolved
Triage: ready-for-agent
Review: 用户已确认网站与公开 API 测试边界；已实现并完成本地验收
Date: 2026-10-13

## Problem Statement

学习者需要在手机和电脑上使用同一套题库，随时接续练习，并积累自己的错题、收藏与学习记录。管理员需要将整理好的题库文件可靠地导入和发布，更新题目时不破坏用户正在进行的练习或历史成绩。只在单浏览器保存数据不能满足这些需求。

## Solution

提供中文响应式在线刷题网站。管理员按模板上传 CSV 或 XLSX，校验、预览、保存草稿并确认发布；注册用户可以练习所有已发布题库。用户通过用户名和密码登录，在手机与电脑间同步练习进度、错题和收藏。首版完成导入发布、日常练习、错题复习、纠错反馈及部署备份的完整流程。

## User Stories

1. 作为访客，我希望使用唯一用户名和密码自主注册，以便建立学习账号。
2. 作为用户，我希望设置可重复的昵称，以便展示姓名而不影响登录标识。
3. 作为用户，我希望登录和退出账号，以便在共享设备上保护个人记录。
4. 作为忘记密码的用户，我希望联系管理员重置密码，以便恢复访问。
5. 作为管理员，我希望在站外确认身份后设置临时密码，以便帮助正确的用户。
6. 作为用户，我希望重置密码后其他设备退出且下次登录必须改密，以便恢复账号控制。
7. 作为管理员，我希望通过同一登录入口进入管理功能，以便管理题库和用户。
8. 作为管理员，我希望创建和编辑题库，以便组织不同主题的题目。
9. 作为管理员，我希望将题目放入一层分类并添加多个标签，以便用户选择练习范围。
10. 作为管理员，我希望下载 CSV 和 XLSX 模板及示例，以便正确整理导入内容。
11. 作为管理员，我希望一次导入单选、多选和判断题，以便覆盖基础客观题。
12. 作为管理员，我希望看到具体错误行和字段，以便修正文件。
13. 作为管理员，我希望任何错误阻止整批导入，以便避免部分写入造成混乱。
14. 作为管理员，我希望预览题目以及新增、更新数量，以便确认导入结果。
15. 作为管理员，我希望通过题目编号更新已有题目，以便避免重复建题。
16. 作为管理员，我希望导入结果先保存为草稿，以便审核后再发布。
17. 作为管理员，我希望修改已发布题目后重新确认发布，以便控制生效时机。
18. 作为用户，我希望只看到已发布题库，以便练习已审核内容。
19. 作为用户，我希望选整个题库或某一分类，以便集中练习。
20. 作为用户，我希望选择顺序或随机练习，以便按自己的学习方式答题。
21. 作为用户，我希望选择 10、20、50 或全部题目，以便安排练习量。
22. 作为用户，我希望不足指定数量时仍可练习实际题数，以便使用较小题库。
23. 作为用户，我希望顺序练习接续上次位置并可从头开始，以便逐步完成题库。
24. 作为用户，我希望随机练习场内不重复，以便每场覆盖不同题目。
25. 作为用户，我希望提交后立即看到正确答案和解析，以便理解错误。
26. 作为用户，我希望提交后锁定答案且可回看，以便成绩反映实际作答。
27. 作为用户，我希望结束时未提交题目不计分，以便统计准确。
28. 作为用户，我希望自动保存当前题目和未提交选择，以便中断后继续。
29. 作为用户，我希望换设备看到已同步的练习状态，以便手机电脑接续。
30. 作为用户，我希望同时操作发生冲突时明确提示刷新，以便旧进度不会覆盖新进度。
31. 作为用户，我希望断网时保留当前选择并显示同步状态，以便知道是否需要重试。
32. 作为用户，我希望答错自动进入错题本，以便集中复习。
33. 作为用户，我希望手动标记已掌握，之后答错恢复待复习，以便控制复习范围。
34. 作为用户，我希望收藏题目并从收藏发起练习，以便复习重要内容。
35. 作为用户，我希望从错题本发起练习，以便强化薄弱内容。
36. 作为用户，我希望新练习使用最新已发布版本，以便学习修正后的内容。
37. 作为用户，我希望进行中和历史练习保留原题与答案，以便题库修改不改变成绩。
38. 作为用户，我希望正确答案变化时原已掌握错题恢复待复习，以便重新学习。
39. 作为管理员，我希望下架题库并归档题目，以便停止新增练习而保留历史。
40. 作为用户，我希望下架后仍能完成已有练习并查看历史，以便学习记录完整。
41. 作为用户，我希望看到继续练习入口及学习统计，以便了解进度。
42. 作为用户，我希望答题后反馈题干、选项、答案或解析错误，以便改善题库。
43. 作为管理员，我希望查看反馈并更新处理状态，以便跟踪纠错。
44. 作为手机用户，我希望答题和管理功能均适配小屏，以便随时使用。
45. 作为部署维护者，我希望使用 Docker、HTTPS 和持久化数据库，以便正式运行网站。
46. 作为部署维护者，我希望每天备份并能按说明恢复，以便故障后恢复服务。

## Implementation Decisions

### 账号与权限

- 用户名唯一，昵称可重复；不收集邮箱或手机号，不提供邮件验证或邮件找回。首位管理员部署时创建，公开注册只能生成普通用户。
- 管理员与普通用户共用登录入口，管理权限由服务端验证。普通用户只能读已发布题库，并只能访问自己的会话、作答、错题和收藏。
- 密码仅保存安全哈希；管理员不能查看原密码。重置操作使既有登录失效，临时密码登录后必须修改密码，完成前不能进入普通功能。站外身份确认由管理员执行，站内记录重置操作。
- 认证使用成熟组件及安全会话 cookie；服务端承担授权与判分，客户端提供的用户标识和成绩不作为可信依据。

### 公共题库与版本

- 建立题库管理、导入发布、练习会话、个人学习记录、反馈处理、认证授权等模块。服务器数据库为跨设备状态的权威来源，本地存储仅辅助保存未同步草稿。
- 题目只属于一个题库，最多一个一层分类，可有多个标签；未填写分类的题目可从整个题库范围练习。
- 题库支持草稿、发布、下架；题目身份与版本分离。编辑和导入更新先成为草稿，发布时才替换对新练习可见的版本。
- 会话固定选题清单、顺序与题目版本；历史保存题干、选项、答案、解析与判分依据，不因之后编辑而改变。
- 下架禁止新建相关练习，允许完成现有会话；归档题目排除新练习，但保留已有会话、错题和收藏记录。已被使用的内容不硬删除。
- 错题和收藏的新练习使用最新已发布且可练习的版本；公布正确答案变更时，把该题已有的已掌握错题恢复待复习，不凭空为从未答错者建立错题。

### 模板与导入

- 首版支持固定字段模板 CSV 和 XLSX；一个导入批次选择一个目标题库，一行一道题。字段包含题目编号、题型、题干、选项、正确答案、解析、分类、标签；解析、分类和标签可选。
- 只支持纯文字单选、多选、判断题。模板定义选项标识及多答案、标签的分隔方式，模板下载与解析规则必须一致；不执行单元格公式或导入内容中的脚本。
- 题目编号在题库内唯一。同编号更新、新编号新增，文件中缺少的题目保留；文件内重复编号报错。判断题答案格式和各字段编码由模板明确规定。
- 校验必要字段、题型、有效选项与答案引用；单选恰有一个正确选项，多选存在有效正确选项集合，判断答案须有效。错误包含行、字段和原因。
- 全批校验通过后展示预览及新增更新数量，管理员确认后原子保存草稿；失败不部分写入。确认发布后普通用户才可见，其他设备下一次读取能取得已发布内容，无需重新导入。
- 导入确认与发布须防重复提交及并发覆盖；导入预览到确认之间的目标数据变化不能被静默覆盖。

### 练习与同步

- 支持顺序、随机、错题、收藏四种模式；默认 20 题，可选 10、20、50 或全部，不足时取实际数量。范围为空时显示说明，不创建空会话。
- 顺序进度按用户、题库及分类范围分别保存，继续时接续位置，也可主动从头开始。随机可抽到过去做过的题，但同一场不重复；会话创建后不重新随机。
- 提交后锁定答案、展示答案解析；多选按集合完全相同才正确，不计部分分。可回看，重答须新开会话。
- 结束时展示已答和剩余题数；未提交题目不计入正确率和错题。重复网络提交只能生成一条作答记录。
- 自动保存当前题目位置、未提交选择和已提交结果；同步成功、同步中、失败或断网须清楚区分。跨设备接续以服务器确认状态为准。
- 通过会话版本检查拒绝过时写入，提示刷新；刷新或重试前保留并提示本地未同步选择，不静默覆盖服务器新状态。
- 首版需要联网；断网可暂存当前选择，但不宣称已提交、已判分或已同步，恢复后重试必须经过版本检查。

### 错题、收藏、统计和反馈

- 答错进入待复习错题；用户可手动标记已掌握，再次答错恢复待复习。收藏独立于错题，允许添加和取消。
- 首页展示继续练习、累计作答、正确率、题库覆盖率、待复习错题数。累计作答和正确率基于所有成功提交记录，重复练习计入；查看历史不新增记录。
- 覆盖率按不同题目去重，基于当前已发布可练习题目集合计算；同一题的版本更新不当作另一道题。没有作答时正确率展示无数据，不产生虚构数值。
- 答题后可提交答案、解析、题干或选项问题及文字说明；反馈关联具体题目版本。管理员可查看并记录处理状态，内容修改仍走草稿发布。

### 交付与界面

- 中文响应式界面覆盖手机与电脑的学习和管理流程，批量导入优先优化电脑操作。操作适配触屏和键盘，重要状态不只依赖颜色。
- 单台服务器 Docker 部署，数据库持久化、HTTPS 配置、每日备份和恢复说明。域名及具体服务器在实际上线前确定；备份恢复需演练。
- 不在本规格锁定前端框架、后端语言或托管厂商。实施需提供本地启动、配置、管理员初始化及迁移说明。

## Testing Decisions

- 测试边界提议：优先通过运行中的完整网站、真实数据库和两个独立浏览器会话验证外部行为，覆盖普通用户与管理员。测试不依赖组件内部状态、私有函数或精确页面结构。此边界已由用户确认。
- 主要验收链路：管理员下载模板、导入并预览、保存草稿、发布；普通用户在电脑选择答案且同步成功；手机继续同一会话、提交、收藏、复习错题；电脑重新读取看到相同结果。
- 浏览器验收覆盖手机与电脑尺寸、登录退出、管理员重置及强制改密、普通用户不能执行管理操作、两个用户记录隔离、统计与历史一致。
- 导入验收使用 CSV 与 XLSX 的等价数据，覆盖三种题型、中文、引号和换行、缺必填字段、非法答案、重复编号、更新及保留缺失题目；失败时数据库无部分写入，草稿对普通用户不可见。
- 会话验收覆盖四种模式、四种题量、不足题数、空范围、顺序接续与重开、随机不重复、锁定提交、未答不计分、重复提交不重复计数。
- 更新验收覆盖草稿不生效、发布后新会话使用新版、已有会话和历史保留旧版、正确答案变化恢复错题、下架和归档禁止新练习但保留记录。
- 同步验收通过两设备同时修改及模拟断网验证版本冲突、失败提示、草稿保留和恢复重试，不能只用改变视口尺寸代替跨设备同步测试。
- 对难以通过界面穷举的授权、幂等、原子导入及并发场景，以服务端公开接口进行补充集成测试；不为每个内部模块重复建立测试边界。
- 既有浏览器检查脚本提供页面操作和小屏检查的参考，但针对旧本地存储产品，不能直接证明本规格完成；现有验证记录不作为本次测试通过证据。
- 部署验收：持久化数据重启后仍在、定时备份生成可恢复备份，并在隔离环境恢复后核对账号、题库、会话和记录。实际 HTTPS 与两设备同步须在部署环境验证。

## Out of Scope

- 个人私有题库、用户上传或公开分享自己的题库。
- 任意文件自动识别、导入字段映射、JSON/Word/PDF/扫描图片导入、图片或公式等富媒体题目。
- 填空、简答、人工评分、多选部分分、模拟考试与考试计时。
- 多层分类、排行榜、支付、广告、间隔复习算法。
- 邮箱或手机号注册、邮件验证或邮件重置密码、第三方登录。
- 完整离线刷题、原生手机应用、多服务器高可用部署。
